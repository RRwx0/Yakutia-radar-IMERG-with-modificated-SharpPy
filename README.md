# IMERG · Саха — реальные наблюдения осадков и наукастинг

Рабочий контур мониторинга осадков над Республикой Саха (Якутия) на реальных данных: снимки GPM IMERG каждые 30 минут, пересчёт в отражаемость, карта, зонд точки и прогноз на два часа.

```
┌──────────────────────┐      ┌────────────────────────┐      ┌─────────────────────────┐
│  Реальные данные     │      │   Сервер обработки     │      │    Клиентское (UI)      │
│  GPM IMERG, 30 мин   │ ───> │   Python + наукастинг  │ ───> │   Карта Якутии (Leaflet)│
│  NASA / JAXA, 11 км  │      │   дБЗ, мозаика, прогноз│      │   тайлы, API, зонд      │
└──────────────────────┘      └────────────────────────┘      └─────────────────────────┘
```

## Почему не ДМРЛ

Настоящих ДМРЛ в Якутии нет, их данные закрыты, а публичные радарные мозаики регион не покрывают (проверено по RainViewer: тайлы над Якутией пустые). Единственные открытые наблюдения осадков по всей территории — спутниковые IMERG. Поэтому источник реальный, но не радиолокационный: разрешение около 11 км, шаг 30 минут, задержка около 7 часов.

## Что делает конвейер

| Этап | Модуль | Что происходит |
|------|--------|----------------|
| Загрузка | `radar/sources/imerg.py` | тайлы IMERG с NASA GIBS, кэш на диск, проверка доступности последнего кадра |
| Декодирование | `radar/sources/imerg.py` | цвет тайла → мм/ч по палитре продукта |
| Сетка | `radar/grid.py` | пересчёт на сетку 0,03° и в дБЗ; Z–R выбирается по фазе осадков |
| Фаза | `radar/phase.py`, `radar/sources/gfs.py` | смоченный термометр по T₂ₘ и RH₂ₘ GFS: снег / смешанные / дождь |
| Наукастинг | `radar/nowcast.py` | оптический поток, адвекция, ансамбль из 5 членов, вероятности |
| Проверка | `radar/nowcast.py` | MAE адвекции против инерции на последней паре кадров |
| Рендер | `radar/tiles.py` | тайлы z3–z6 со шкалой отражаемости |
| Сборка | `radar/pipeline.py` | манифест, пробные сетки, `client/data.js` |
| Отдача | `server/app.py` | FastAPI: состояние, зонд, тайлы |
| Интерфейс | `client/` | Leaflet: таймлайн, шкала, зонд, прогноз |

## Наукастинг и его честность

1. Оптический поток Хорна–Шунка по двум последним кадрам.
2. Полулагранжева адвекция на 4 шага по 30 минут.
3. Ансамбль: 5 членов с разбросом скорости и интенсивности → вероятность ≥30 и ≥45 дБЗ.
4. Автовыбор: если на последней паре адвекция хуже инерции, прогноз строится по инерции. Текущий метод и MAE пишутся в манифест.

На реальных 30-минутных кадрах адвекция часто проигрывает инерции — это ожидаемо для разреженного поля и честно показывается в интерфейсе и манифесте, а не подгоняется.

## Точность: фаза осадков и Z–R

Отражаемость пересчитывается по фазе, а не одной формулой:

- дождь — Z = 200·R¹·⁶ (Marshall–Palmer);
- снег — Z = 2000·R² (снежная связь, даёт заметно другие дБЗ при той же мм/ч);
- смешанные — взвешивание в Z по смоченному термометру.

Фаза определяется по T₂ₘ и RH₂ₘ GFS через смоченный термометр (Stull, 2011): Tw ≤ 0,5 °C — снег, 0,5–2 °C — смешанные, выше — дождь. Это точнее, чем порог по сухой температуре: при высокой влажности снег идёт и при слабоположительной T.

В интерфейсе: переключатель «Фаза осадков» (голубой — снег, сиреневый — смесь, слабый синий — дождь), доля снега в HUD, фаза и Tw в зонде, фаза учитывается в мм/ч зонда.

## Опасная гроза

`radar/severe.py` складывает индекс из максимума дБЗ, площади и роста ячейки, CAPE и сдвига 0–6 км из GFS. Это прокси условий опасной грозы: молний и доплера нет, поэтому разряд не фиксируется.

Мезоциклон **не детектируется**: для вращения нужна радиальная скорость доплеровского радара, которого в Якутии нет.

## Гроза, ливень, дождь или снег

Каждая ячейка ≥35 дБЗ получает тип в `radar/classify.py`:

- **гроза** — компактное ядро ≥45 дБЗ, высокий градиент, CAPE ≥700–1200 Дж/кг, сдвиг ≥15 м/с, рост;
- **ливень** — сильное эхо без достаточной неустойчивости;
- **дождь** — слабое или среднее эхо, низкие CAPE и градиент;
- **снег** — фаза «снег»; порог по дБЗ ниже, конвекция оценивается отдельно;
- **смешанные** — фаза «смесь» без признаков грозы.

Признаки: пик и среднее дБЗ, площадь ядра ≥45, заполнение bbox, градиент, CAPE, сдвиг, рост между кадрами, фаза. У каждой ячейки есть `confidence` (0–1) и `reasons` — их видно в подсказке маркера. Цвета: красный — гроза, оранжевый — ливень, синий — дождь, голубой — снег, сиреневый — смесь.

Это прокси: молний и доплера нет, поэтому «гроза» означает «условия грозы по эху и среде», а не зафиксированный разряд.

## Быстрый старт

```bash
pip install -r requirements.txt
python -m radar.pipeline
python -m uvicorn server.app:app --host 127.0.0.1 --port 8080
```

Интерфейс: <http://127.0.0.1:8080>. Можно открыть `client/index.html` напрямую: тайлы лежат в `client/tiles`, снапшот — в `client/data.js`.

## Публикация: GitHub Pages + Render

Самый простой способ загрузить проект — двойной клик по **`publish.bat`**
(см. `PUBLISH.md`). Дальше — фронтенд на GitHub Pages, API на Render.

1. Создайте репозиторий на GitHub и запушьте проект в ветку `main`.
2. На Render: **New → Blueprint**, выберите репозиторий — `render.yaml` подхватится сам.
   Либо **Web Service** вручную: build `pip install -r requirements.txt`,
   start `uvicorn server.app:app --host 0.0.0.0 --port $PORT`.
3. Скопируйте адрес сервиса, например `https://yakutia-radar-api.onrender.com`.
4. В `client/config.js` пропишите этот адрес и запушьте:
   ```js
   window.API_BASE = "https://yakutia-radar-api.onrender.com";
   ```
5. В GitHub: **Settings → Pages → Source: GitHub Actions**.
6. Сайт откроется по адресу `https://<логин>.github.io/<репозиторий>/`.

Важно: `client/tiles/` и `client/data.js` должны быть в репозитории — это снимок радара для Pages.
Бесплатный Render засыпает без трафика (первый запрос ~30–60 с), а архивы IGRA
скачиваются при первом обращении к станции и живут до перезапуска инстанса.

## API

| Метод | Назначение |
|-------|------------|
| `GET /api/state` | манифест: кадры, статистика, метод прогноза, источник |
| `GET /api/probe?lat&lon&frame` | отражаемость, класс, вероятность, тренд |
| `GET /api/accum?lat&lon&frame&window` | сумма осадков за окно, мм |
| `GET /api/archive?date&hour` | сборка/выдача архива за 6 часов (с 2025-01-01) |
| `GET /api/archive/status?key` | состояние сборки архива |
| `GET /tiles/{frame}/{z}/{x}/{y}.png` | тайлы |
| `GET /api/health` | состояние сервиса |

## Архив с 2025 года

Панель «Архив» в шапке: дата (с 1 января 2025 до сегодня) и час по Якутску. Сервер поднимает 12 кадров за 6 часов, считает накопления, рендерит тайлы и складывает результат в `data/archive/{date}_{hour}.json` и `client/tiles/a…`. Повторный запрос той же даты отдаётся из кэша мгновенно. Кнопка «К текущим данным» возвращает live-режим.

Сборка идёт в фоне: клиент опрашивает `/api/archive/status` и показывает прогресс.

## Параметры

- отражаемость, дБЗ (Z–R по фазе: дождь 200·R¹·⁶, снег 2000·R², смесь — взвешивание);
- интенсивность, мм/ч (исходное значение IMERG, пересчёт с учётом фазы);
- фаза осадков и доля снега в эхе (смоченный термометр GFS);
- ячейки ≥35 дБЗ: площадь, максимум, рост между кадрами;
- индекс опасной грозы: дБЗ, площадь, рост, CAPE, сдвиг;
- накопление за окно, мм (сумма R·0,5 ч по кадрам);
- площадь ≥30 дБЗ, тыс. км², и доля эха;
- тренд за 90 минут и вероятность ≥30 дБЗ для прогноза.

Карта: рельефная подсветка Esri, свечение слоя осадков, координатная сетка 10°/5°, масштабная линейка и компас.

## Режимы

Панель «Режимы» в шапке. Честные статусы: два режима работают, три недоступны без прямого фида.

- **Beam-rise** — расчёт высоты луча с поправкой 4/3 радиуса Земли для углов 0,5°, 1,5°, 2,4°; график до 250 км и высоты на 50/100/150/200/250 км. Это геометрия, а не данные.
- **Эфирный интерфейс** — высококонтрастная тема (чёрный фон, красные и голубые акценты, крупные подписи), вдохновлённая broadcast-подачей; состояние хранится в localStorage. Не является официальным оформлением чужого продукта.
- **Direct-to-sensor** — недоступно: в Якутии нет ДМРЛ и публичного фида. Появится при подключении источника в `radar/sources`.
- **Вертикальный профиль шторма** — недоступно: нужны полярные объёмы по углам места (ДМРЛ или GPM DPR); IMERG даёт только приземную интенсивность.
- **Ультранизкая задержка** — недоступна: IMERG Early Run публикуется с задержкой около 7 часов, фактическая задержка последнего кадра показывается в панели.

## Ограничения

- Спутниковая оценка сглаживает локальные ливни; слабый снег может не фиксироваться.
- Отражаемость в дБЗ — расчётная величина (Z–R), а не измерение радара; снежная связь снижает, но не убирает неопределённость.
- Фаза берётся из GFS (модель, шаг ~0,25°), а не из наблюдений; у границы 0 °C возможны ошибки.
- Колдринг и мезоциклон не рассчитываются: нет ИК-поля и доплеровской скорости.
- Задержка публикации около 7 часов; это наблюдения и краткий прогноз, не официальное предупреждение.
- Валидация прогноза — самопроверка на последней паре кадров, не независимая выборка.

## Подключение реального радара

Если появится легальный доступ к объёмам ДМРЛ (NetCDF/HDF5, полярная сетка), замените `radar/sources/imerg.py` на адаптер, возвращающий поле на `Grid`, и включите шаг QC/мозаики из `radar/qc.py` и `radar/mosaic.py` — они сохранены в проекте. Остальные шаги не меняются.
